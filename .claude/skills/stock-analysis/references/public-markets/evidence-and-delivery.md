# 数据契约、证据追溯与交付核对

改编自 Public Markets Investing 的 execution-standard、source-and-artifact-contracts、financials-normalizer、deliverable-qc。来源见 [sources.md](sources.md)。数据跨模块流转、形成模型或更新正式研究时读取。

## 研究上下文与取数

固定标的/证券类别、市场、研究问题、期限、截至时间、财年、会计口径、财报/交易/展示币种、行情时段、深度和交付格式。沿用用户已指定的格式和授权；普通问答直接回答，已有项目页面沿用格式，仅在缺失信息会实质改变任务时询问。

先列所需数据能力：证券身份、行情、公司行动、原始报表、分部、预期、官方公告、宏观或股权数据，再核查本环境实际可调用工具。能力名称是需求描述，不代表已安装 API。可用专业源按覆盖选择，财报优先一手披露；不可用时使用可核验公开原件或用户材料，记录降级原因和覆盖差异。权限、超时、参数错误不能记成「无数据」；只有调用成功且返回所需字段后才称数据可用。

引用放在所支持的数字或判断旁；记录原始文档链接/页码或接口返回的有效引用，不能生成假的文档名、日期或数据集。保留抓取时间、有效日期、报告期和可得时间，分清最新报价、历史快照及盘中/收盘。

## 证据登记

| 类型 | 中文含义 | 使用边界 |
| --- | --- | --- |
| reported | 已披露事实 | 官方文件的原文、期间和口径；不自动把发行人预测算成事实 |
| market_observation | 市场观测/共识快照 | 时间戳和覆盖；共识仍是预测，不能称实际结果 |
| issuer_statement | 管理层声明 | 归属说话者、材料和时间，不升级为兑现结果 |
| model_result | 模型输出 | 可复现输入、公式、脚本或工作簿位置 |
| scenario_input | 情景假设 | 区间、理由、关联假设和敏感性 |
| research_view | 研究判断 | 支持证据、反证、置信度与失效条件 |
| unresolved | 待核实 | 缺失原因、对结论的影响及补证路径 |

原包的 management_statement / inference 等旧标签分别映射为管理层声明 / 研究判断，统一入口中的中文标签保持有效。用户材料说明提供者和核验状态，不能因为是用户提供就默认已核实。

多模块共用轻量证据包；可用 Markdown 表或结构化文件，不要求每次问答生成 JSON：

- sources：稳定 ID、原件位置、发布/有效/获取日期与覆盖限制。
- claims：主张、证据类别、支持来源 ID、反证及置信度。
- key_figures：指标、数值、单位、期间、币种、口径、原始值/调整/计算关系。
- review_issues：未解决问题、影响的结论、下一步证据、复核节点与是否阻止该结论成立。
- visuals：需要图表时记录来源表、转换与展示位置。

ID 必须能解析、重复指标必须一致、原始与计算字段分开。证据不足只限制受影响结论，不把全部研究强行中止或补成精确数字。

## 交付核对

结论 → 业务证据 → 假设/预测 → 估值 → 催化 → 反证必须连通。结论卡、正文、表格和图表里的价格、股数、净债务、利润和估值一致；单位、正负号、期间、币种和报告范围能勾稽。图表从同一冻结数据表生成。

区分「工作草稿」（关键缺口或核对未完成）与「已复核」（本次范围内证据、计算和展示已检查）；写明未核实部分，不把标签当正确性保证。只在用户要求文件时制作相应文件，复杂计算可附可复现模型。HTML、PDF、表格或幻灯片使用当前可用工具，按格式检查实际渲染、引用和数字；未渲染的文件不能称已视觉核验。

研究交付不包含下单、静默上传或自动部署。用户已经授权的项目更新直接完成；不继承原包对所有输出强制追问格式、双语、多人编排或额外审批的要求。
