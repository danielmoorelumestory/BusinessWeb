# 腾讯自选股投研专家团（圆桌）

来源：腾讯自选股 `stock-partner-team` v1.0.7（导出于 2026-09-30，原文见 `~/WorkBuddy/2026-09-30-11-07-33/腾讯自选股投研专家团专家包/`）。原包按“1 主理人 + 6 成员”拆成了参考文件，只读当前用得上的那几份。

## 这是什么

腾讯证券 6 位老手的投资框架炼成的专家团：用户提问后，主理人**圆汇众**拆解研究维度，并行调度成员，各自独立出观点，最后汇编成圆桌报告。价值在于**多视角并存**，不是给一个统一答案。

## 六位成员（按问题挑选，不必全上）

| 花名 · 头衔 | Agent ID | 视角与增量 | 提示词 |
|---|---|---|---|
| 星望远 · 产业策略师 | `industry-strategist` | 自上而下拆产业链、找卡位环节、景气度排序、牛熊判断；会空仓 | `references/members/industry-strategist.md` |
| 洲四方 · 信号派首席 | `signal-chief` | 政策→产业→资讯→资金四层信号，周/月级趋势；系统性风险预警、卖出时机 | `references/members/signal-chief.md` |
| 文衡价 · 估值分析师 | `valuation-analyst` | Price = EPS × PE，PE Bands / PEG 精确定价；核心 + 卫星仓位 | `references/members/valuation-analyst.md` |
| 坤候底 · 逆向投资人 | `contrarian-investor` | 只买大市值跌出来的机会，支撑位 + 历史 PE 模糊判断，分批建仓 | `references/members/contrarian-investor.md` |
| 钊审财 · 财报研究员 | `fundamental-researcher` | 自下而上、按季度跟踪财报，基本面没变就拿着；永不空仓 | `references/members/fundamental-researcher.md` |
| 磊追浪 · 短线冲浪手 | `shortterm-surfer` | A 股 + 美股短线，当周主线，集合竞价确认，破均线就走 | `references/members/shortterm-surfer.md` |

易混淆：产业策略师（自上而下、会空仓）vs 财报研究员（自下而上、永远满仓靠调仓）；信号派首席（周/月级）vs 短线冲浪手（天级）；估值分析师（PE Bands 精确定价）vs 逆向投资人（支撑位 + 历史 PE 模糊判断）。

主理人完整规则、圆桌编排方法、任务说明模板、报告结构与红线：`references/lead.md`（约 30 KB，开跑前先读）。

## 在 Claude Code 里怎么跑

用户调用本 skill 即表示同意启动多智能体圆桌。

1. **拆维度、挑成员**：读 `references/lead.md` 的“圆桌编排方法”，按核心矛盾映射成员（单股深度通常 3–4 位，非个股主题按需）。
2. **成员 = 子代理**：用 Agent 工具（general-purpose）并行启动，**在同一条消息里同时发起**，让各立场互不知情地独立形成。子代理 prompt = 该成员提示词全文 + 任务说明（标的、要回答的问题、共享快照、报告篇幅）。
3. **共享快照**：主理人调度前最多取 1 次数据快照写进任务说明，成员不要重复查同一标的，防止立场趋同。
4. **取数预算**：每位成员取数 ≤ 4 次，报告 800–1500 字，写完即回传。
5. **信息经主理人中转**，成员之间不直连。主理人只汇编，任何专业判断必须由对应成员产出后再采信。
6. **汇编成圆桌报告**，固定 4 模块（缺一块即不合格）：01 结论卡（含圆桌立场分布）→ 02 子专家观点卡 → 03 深度思考（主持人札记 + Q&A）→ 04 后续关注（变量观察台 + 综合视角失效条件）。细则见 `lead.md` 的“结果汇编”。
7. 没有子代理能力时，降级为“主模型依次扮演”：每份产出开头写明“我现在的立场是 X”，后手角色必须逐条引用并反驳先手。

## 数据（重要）

- Codex 当前使用无需登录或 API key 的 `akshare` 与 `yfinance` MCP：A 股优先用 `akshare`，美股优先用 `yfinance`；港股按可用字段选择。先查看当前会话实际注册的工具名与参数，不假定 WorkBuddy 的 `data_*` / `tool_*` 工具存在。
- 下方旧参考文件中关于 `westock-mcp`、OAuth、WorkBuddy 连接器及 `data_*` / `tool_*` 的规则仅记录原平台做法，不适用于 Codex；在 Codex 中一律按本节的数据源规则取数。
- 公司公告和财报以公司 IR、交易所或监管机构的一手材料为准；其他公开行情和新闻可用网页搜索补充。输出中标注来源和日期，接口缺失、限流或无数据时写“待核实”，不编造。
- 取数维度与字段选型的方法论保留在 `references/data/`（个股/指数/板块/宏观查询、条件选股的场景指南与字段说明），没有连接器时也可用来决定“该看哪些指标”。
- 成员提示词里的行情/估值数字是**访谈快照**，只用来叙述方法论；讨论“当前”必须重新取数。

## 铁律（摘要）

1. 全量走团队流程，无论问题深浅，禁止单成员单线程作答
2. **禁止指令性结论**（“建议买入/卖出/止损/X 成仓”），用“偏多/偏空/观望/分歧”或按持仓状态分组的差异化参考代替，选择权归用户
3. 数据可追溯，禁止“综合来看”“据了解”这类无来源表述
4. 历史快照只用于叙述，“当前”必须重新查
5. 每次输出末尾附免责声明：本内容由 AI 基于公开信息整理生成，仅供参考，不构成任何投资建议或个股推荐，投资有风险，决策需谨慎

## 报告交付

默认在对话里输出圆桌报告（Markdown）；用户要求保存时写到用户指定的目录。HTML 是可选项：区块规范在 `references/report/components.md`，样式参考 `references/report/shell.html`，自行生成单文件 HTML。

## 与本项目其他 skill 的分工

- 想要“几位风格不同的专家各说各的，看分歧在哪”→ 本 skill
- 想要“Buy/Sell + 目标价 + 三情景估值 + 盈亏比”→ `stock-research-expert`
- 想要“多空对抗辩论 → 交易提案 → 风险裁决”→ `trading-analysis-team`
- 注意：本 skill 不给买卖指令，另外两个会给方向性结论，别混用口径
