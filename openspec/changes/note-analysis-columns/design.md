## Context

12 篇标的分析笔记（文件名 `public/notes/<6 位代码>-<名称>-analysis.md`）的「## 一、结论速览」都是同一种表：`| 维度 | 最终判断 | 关键依据 |`，其中以「短期」开头的行与以「中期（」开头的行就是要的内容，最终判断单元格里偶有 `**粗体**`。已保存标的页由 `saved.astro` 用模板字符串渲染 19 列的表格，数据来自浏览器本机记录与云端同步；Worker `grid-trading-sync` 已有带同步密钥的读取接口（如 `/daily/extremes`）和前端对应的读取函数。

## Goals / Non-Goals

**Goals:**
- 笔记里的短期、中期最终判断进云端数据库，并在已保存标的页显示。
- 笔记更新后能重复运行脚本刷新数据。

**Non-Goals:**
- 不做自动触发（笔记发布后仍需手动运行一次脚本）。
- 不对判断文字做情绪分类、着色或排序。
- 不在详情页显示（本次只做已保存标的页）。

## Decisions

1. **单独建表，不放进用户记录。** 记录里的 `levels` 是用户可编辑的数据，而这里的判断是笔记派生的只读内容。若写进记录，必须改记录的 `updatedAt` 才能被同步，会覆盖用户本机尚未上传的修改；单独建表则完全没有这个冲突，也能服务尚未保存回测的标的。表结构：`note_analysis(code TEXT PRIMARY KEY, slug TEXT, title TEXT, as_of TEXT, short_judgment TEXT, mid_judgment TEXT, updated_at INTEGER)`，每个代码一行。
2. **解析规则。** 在「## 一、结论速览」小节内找表格；第一列以「短期」开头的行取第二列为短期判断，以「中期（」开头的行取第二列为中期判断；去掉 `**`、反引号等标记并压缩空白。找不到任一行的笔记跳过并在脚本输出里列出，不写入。代码取文件名开头的 6 位数字，数据基准日取正文「数据基准：YYYY-MM-DD」，取不到则为空。同一代码有多篇笔记时取数据基准日最新的一篇（相同则取 slug 字典序较大者）。
3. **入库方式。** 脚本只生成 SQL（`INSERT … ON CONFLICT(code) DO UPDATE`），用 `wrangler d1 execute grid-trading-sync --remote` 执行；默认先 dry-run 打印将写入的内容，加参数才真正写入。解析与 SQL 生成放在可单测的模块里，脚本只负责读文件与调用。SQL 中的字符串按单引号转义。
4. **读取接口。** `GET /analysis?codes=a,b,c`（一次最多 50 个），需要同步密钥，返回 `{ analysis: { [code]: { slug, title, asOf, short, mid } } }`，没有记录的代码不出现；表不存在时返回空结果而不是报错，便于先部署 Worker 后建表。
5. **前端。** `fetchNoteAnalysis(codes)` 仿照 `fetchCloudExtremes`：没有同步密钥、请求失败或超时都返回空 Map，页面显示「—」，不影响其余功能。已保存标的页渲染后异步读取一次，拿到后只更新这两列的单元格（不整表重绘，避免打乱排序与滚动位置）。
6. **显示。** 两列放在「名称」之后，列宽约 200px、文字 12px、最多 3 行（超出省略），`title` 显示完整判断与「数据基准 YYYY-MM-DD · 点击查看完整分析」；单元格内容是指向对应笔记的链接，地址用 `MAIN_SITE`（Cloudflare 构建为 `/`，本地预览为线上地址）拼出 `notes/<slug>/`，新窗口打开。
7. **部署顺序。** 先对线上 D1 建表，再部署 Worker，再运行入库脚本，最后推送前端；前端在 Worker 或数据缺失时自动降级，所以顺序出错也不会影响现有功能。

## Risks / Trade-offs

- [笔记改版导致表格结构变化，解析不到] → 脚本对解析失败的笔记逐篇报告并跳过，已有数据保持不变。
- [笔记发布后忘记运行脚本，列表里的判断是旧的] → 单元格悬停显示数据基准日，能看出新旧；后续可再考虑自动化。
- [判断文字较长，窄屏下挤占表格] → 限定列宽与行数，完整内容靠悬停提示和链接查看。
- [直接写线上 D1] → 脚本默认 dry-run，写入需显式参数；写入前后各查询一次核对行数。

## Migration Plan

1. 对线上 D1 执行建表（`CREATE TABLE IF NOT EXISTS`）。2. `wrangler deploy` 部署 Worker。3. 运行脚本把现有笔记结论写入。4. 推送前端并线上验证。回滚：前端回退提交即可，表与 Worker 接口可保留。
