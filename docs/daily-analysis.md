# 每日分析自动采集

新版 `/daily-analysis` 进入即加载行情，盘中查看最新数据时每分钟刷新，也可手动刷新。按数据源实际交易日期展示，不把周末、休市或过期数据改成今天。旧手工版迁移到 `/daily-analysis/legacy`，继续使用原 `pulse_daily_reviews` 本地记录、编辑、导入导出及可选云同步。

## 数据与口径

| 内容 | 来源与计算 |
| --- | --- |
| 上证、深证、创业板指数 | 腾讯行情，以报价中的交易日期核验 |
| 沪深成交额 | 上证与深证成交额相加，亿元；不重复加入创业板 |
| 涨停、炸板、跌停 | 东方财富对应股池，核验 `qdate`、总数、完整性和重复证券 |
| 涨停封板率 | 涨停数 ÷（涨停数 + 炸板未回封数） |
| 连板数、高度、梯队 | 涨停股池 `lbc` 连续板数；不把 N 天 M 板当连续板数 |
| 连板晋级率 | 昨日涨停与今日涨停交集 ÷ 昨日涨停数；须有准确前一交易日的已核验涨停归档。当前交易日历覆盖 2026 年，其他年份留空 |
| 成交额、换手率前五 | 新浪沪深京 A 股排名候选 + 腾讯同交易日报价复核 |
| 行业资金流 | 新浪行业净流量，亿元；源未标注交易日期，明确显示采集时刻，不称为主力净流入 |

全市场上涨/下跌家数、跌停打开数、跌停封板率暂缺可靠数据，显示 `—`。首次归档没有昨日股池时，晋级率也显示 `—`。源失败、日期不一致或数据不完整时不填假零值。

## 多日对比

页面上方的「多日对比」按交易日一行展示涨停、封板率、炸板、跌停、量能、连板、最高板、晋级率、沪深创涨跌和前 2 名流入/流出板块，▲▼ 为较前一交易日的变化，可切换近 5/10/20 日，点日期可查看当天完整复盘。

- 涨停、封板率、炸板、跌停、连板、晋级率可一次性回补：`npm run daily-analysis:backfill [天数]`。东方财富股池按 `date` 参数返回历史数据（响应里的 `qdate` 只是最新交易日，不是请求日期），每个日期都用财联社的最高板与连板股数交叉核验，对不上或核验失败的日期不写入。东方财富只保留最近约一个月（2026-09-14 及之后可取，09-11 及更早为空）。回补快照不含榜单、资金流和成交额，已存在的日期不覆盖。
- 量能只来自真实归档快照：腾讯 K 线是成交量不是成交额，东方财富 K 线暂不可用，缺口不插值、不补 0。
- 上证、深证成指、创业板指的日涨跌可由腾讯日 K 线回补；连板数和最高板可由财联社 `/api/cls-plate` 按日期回补（2026-10-12 与归档快照逐项一致，返回日期与请求日期不符、无涨停股时丢弃）。回补日期标「回补」，其余列显示 —。
- 回补的连板数只请求没有快照的交易日，历史数据不会再变，结果缓存在浏览器本机；单日失败不影响其他日期，下次进入页面再试。
- 财联社的涨停股去重数与东方财富涨停股池口径不同（同日 59 对 46），所以涨停数不回补。
- 成交额无法回补：腾讯 K 线的成交量单位是股，与快照中的成交额（亿元）口径不同，不混用。
- 归档不足 2 天时只显示说明，不绘制趋势图。
- 趋势图支持鼠标悬停、触摸或左右方向键查看某一天的读数及较前一交易日变化。
- 「成交额前五」「换手率前五」两列收起时只显示这 5 只股票里上涨/下跌（及平盘）只数，点击展开看每只股票的名称、涨跌幅与成交额（亿）或换手率。新浪榜单没有历史日期，历史日期用 baostock 一次性回补：先运行 `python scripts/python/collect_rank_history.py 起始日 结束日 输出.json`（需 `pip install baostock`，沪深约 5000 只、十几分钟），再运行 `npm run daily-analysis:rank-backfill 输出.json` 并入归档。写入前会用已归档的真实榜单（前五代码与顺序）核对，不一致的榜单类型整体不写入；已有榜单的日期不覆盖。baostock 不含北交所，因此换手率榜要再运行 `node scripts/daily-analysis-bj-turnover.mjs 输出.json 合并后.json 最新交易日` 并入北交所：北交所换手率 = 日线成交量 ÷ 流通股本，流通股本由最新交易日的成交量 ÷ 换手率（腾讯报价）反推，所以是**按当前流通股本的估算**，股票解禁或扩容之前的日期可能偏高；沪深部分是交易所口径。并入后 2026-10-12（含北交所宇特光电）与真实榜单完全一致才写入，但这一天的北交所流通股本正是从当天反推的，不构成独立验证。成交额榜不受影响（北交所成交额很小）。

## 运行与归档

- `npm run dev` 自带 `/api/daily-analysis` 中间件；Vercel 使用 `api/daily-analysis.js`。服务器仅请求固定行情地址，不需 API 密钥。
- GitHub Pages 通过 `VITE_API_BASE` 请求 Vercel API，同时加载站内 `public/data/daily-analysis.json` 历史快照。
- 实时请求限时 18 秒，归档请求限时 8 秒；接口失败时采用归档与浏览器已保存快照，并显示失败提示。浏览器缓存使用独立键，保留最近 60 个交易日。
- 手动归档：`npm run daily-analysis:update`。仅当真实交易日期为当天、且北京时间 15:15 后采集时落盘；休市及盘中不创建伪造日档。同一天二次采集不以更差的完整度覆盖已存归档。
- `.github/workflows/daily-analysis-snapshot.yml` 配置工作日北京时间 15:35、17:10 两次归档。更新文件后提交快照并触发 Pages 构建。工作流需随代码推送到默认分支后才生效；实际执行时刻受 GitHub 调度影响。
- 历史只保留已真实采集的快照，不把旧手工记录混为自动统计，也不承诺补全未曾归档的过去日期。

本次已实际采集并保存首个 2026-10-12 快照。公开行情接口无可用性承诺；每项来源、日期及异常说明可在页面「数据来源与口径」查看。
