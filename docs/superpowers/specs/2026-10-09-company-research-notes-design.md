# 公司研究笔记：公开阅读、Token 编辑

## 用户目标与已确认约束

候选池中的公司需要持续、仔细分析。用户可以上传 Markdown 笔记，在网站阅读、编辑并保存到云端。访客无需登录即可阅读；上传、新建、修改必须验证主人的 token。公司研究笔记与原有私人知识库分别管理。

## 首版使用流程

候选池每家公司新增“研究笔记”入口，公司详情页也提供相同入口。独立页面 `/research-notes/company/:market/:code/notes` 展示该公司的笔记列表。通过 `?note=<uuid>` 可分享具体笔记；公司名称优先复用公司库，市场与代码作为稳定关联键。

访客可以查看列表、阅读完整 Markdown 和下载 `.md`。未填写 token 时不显示可操作的写入表单，显示“解锁编辑”按钮。

主人输入 token 后，服务端验证成功才启用新建、上传和编辑。每家公司支持多篇笔记，例如首次分析、财报更新、估值复核。上传使用本地文件选择器，仅接受 UTF-8 `.md`，大小不超过 1 MiB；上传内容先进入编辑草稿，点击保存才写入云端并公开。空文件、非法编码、空标题和超限正文明确报错。正文保留用户原文。

编辑页面支持编辑和阅读预览切换、显式保存与 Markdown 下载。显示保存中、已保存和失败状态。保存失败保留草稿；页面内切换和离开时提醒未保存变更。锁定编辑清除本会话凭据，访客阅读仍可用。

## 方案选择

推荐独立公司笔记表及独立 API，复用现有 Supabase 连接、Bearer token 校验和 MarkdownPreview 组件。其他方案包括开放现有知识库目录、仅保存在浏览器；前者会改变私人资料授权与同步规则，后者不能实现跨设备公开阅读。本次采用独立公司笔记方案。

不修改 `/api/knowledge` 的鉴权、只读行为和 Obsidian 同步规则。不把上传的公司笔记隐式同步到私人 Obsidian 目录。

## 数据与服务接口

新增表 `businessweb_company_research_notes`：`id`（UUID）、`market`、`code`、`title`、`content`、`revision`（正整数）、`created_at`、`updated_at`。市场与代码校验复用候选池规则。索引支持按 market/code 和更新时间查询。

表启用 RLS，浏览器 anon/authenticated 不直接读写，由服务端 API 使用既有 `SUPABASE_URL` 和 `SUPABASE_SECRET_KEY` 访问。

新增 `/api/company-notes`：

- GET `action=list&market=...&code=...&offset=...`：公开分页元数据，不含正文，每页 50 条，并返回是否有下一页。
- GET `action=note&id=...`：公开读取一篇笔记完整内容。
- POST `action=unlock`：检查 Bearer token，成功仅返回授权状态。
- POST `action=create`：授权后创建一篇笔记，revision 从 1 开始。
- POST `action=update`：授权后按 id 和 expectedRevision 原子更新标题、正文，成功返回新版本；冲突返回 409，保留客户端草稿，允许下载并重新加载云端版本。

写入 token 使用独立服务端环境变量 `COMPANY_NOTES_WRITE_TOKEN`，至少 32 字符。复用现有数据库凭据，不复用知识库同步 token，也不把服务端密钥写入前端构建。凭据通过 Authorization header 传递，客户端仅保存在 sessionStorage，退出编辑清除。缺少编辑 token 不影响已配置数据库的公开阅读，写操作返回 503；无效 token 返回 401。服务端每次写入重新鉴权。

创建、更新仅支持 POST，明确拒绝错误方法、未知 action、非法参数。请求设置字节限制，正文单篇上限 1 MiB，标题 1–200 字符。禁止把 token、正文或数据库错误细节写入公开日志和错误响应。

更新通过新增数据库 RPC 在同一事务比较版本并递增版本；并发编辑不能静默覆盖。创建使用客户端生成的 UUID，重复提交相同 id 不覆盖已有笔记。

API 支持现有 Vercel 与 GitHub Pages 来源的 CORS，开发通过 Vite 代理访问；公开读请求不需 token，浏览器 token 不进入 URL。返回 Cache-Control: no-store，避免更新后继续显示旧版本。

## 展示与范围

Markdown 展示复用现有 MarkdownPreview，标题、表格、代码块和链接按现有方式渲染，不执行上传的脚本。新笔记可选提供公司分析模板（核心判断、商业模式、财务、估值、风险反证、下一次验证、来源），不强制上传笔记套用模板。

本期不提供删除、附件上传、多人账号、全文搜索、完整版本历史和私人草稿发布系统；保存即公开，保存按钮附近明确显示这一点。笔记数量与更新时间先在公司笔记列表显示，候选池提供入口；候选池聚合数量徽标可在后续扩展，避免列表逐家公司请求。

## 验证与交付

服务端验证公开无 token 阅读、未授权写入拒绝、合法 token 保存、非法输入拒绝、重复创建与并发更新冲突。界面验证上传、预览、保存、重新加载、下载、解锁与锁定，以及失败后草稿保留。回归原候选池和私人知识中心，并执行相关类型检查、函数检查与构建。

交付包括数据库迁移、前后端代码、测试和部署说明。上线需要运行新增迁移、在托管环境配置编辑 token，并部署 API 与前端；本地实现通过检查不等于已在云端生效。凭据配置使用既有受保护配置流程，不要求用户在聊天中发送实际 token。
