# Live 博客设计（2026-10-13）

## 目标与现状

在现有 Live 站点内建立可持续更新的博客，让读者从投资、AI 编程和自由生活的文章进入书、工具与其他研究页面。博客应在桌面和手机上都能轻松浏览、搜索和连续阅读，并为以后开展内容转化留出真实、可配置的入口。

用户指定的 [gupiaoWS 仓库](https://github.com/danielmoorelumestory/gupiaoWS) 当前只有 `master` 分支；截至本次查看的 `d381540` 提交，它包含《慢即是快》的 Markdown 书稿、专题、审稿建议和修订记录，没有独立的博客文章目录。书稿正文已在本站“我的书”发布。因此首版不把整本书或审稿材料自动转换成博客文章，也不编造发布日期和作者署名。博客上线时即使没有已发布文章，列表、阅读路由和内容导入流程仍应完整可用，空状态引导至已有的书与工具。

## 选择的方案

博客作为 BusinessWeb 内的独立栏目，文章在构建时打包为本站内容。维护者可从 gupiaoWS 仓库或其他本地目录选择 Markdown 文件，通过显式发布清单导入；以后源仓库出现 `blog/` 目录时同一流程继续适用。文章页面使用本站路由、设计 token、SEO 和预渲染流程。

曾考虑运行时直接读取 GitHub 文件。它会让文章可即时变更，但页面可用性依赖 GitHub API、存在请求限额，且搜索与预渲染更难稳定。另一个选择是单独建立博客站；它会重复导航、样式与部署管理，也不利于读者在文章和现有书、工具间移动。当前规模选择站内静态内容更合适。

## 内容契约与兼容规则

- 本站的已发布文章由 `src/content/blog/manifest.json` 登记。每条包含稳定 `slug`、标题、摘要、栏目、标签、发布日期、可选修订日期、Markdown 文件名和可选原始来源。只有明确登记且状态为 `published` 的文章进入公开列表和站点地图。
- Markdown 文件保留原文，支持常用标题、引用、列表、表格、代码块、外链、图片和普通相对链接。文章目录从正文标题生成，标题锚点稳定且重复标题不会碰撞。
- 导入命令从用户指定的本地仓库目录读取发布清单中的文件，复制文章和被引用的本地图片，检查文件路径不越界、链接目标是否存在、slug 是否重复。它不会扫描整个仓库猜测哪些文件应发布。
- gupiaoWS 现有书稿文件没有博客元数据。若以后明确选中某个专题作为博客文章，维护者先在发布清单中提供标题、摘要、发布日期与来源链接；源文件的 Git 提交时间只作为来源核对信息，不冒充文章发布日期。书稿中的“修订记录”“审稿建议”“优化待办”默认排除。
- 保留文章来源仓库与原始路径，便于日后同步及核对。文章内容随本站构建发布，线上阅读不依赖 GitHub 实时可用。
- 渲染 Markdown 时过滤脚本、事件属性和危险 URL；站内相对资源链接映射到本站博客资源目录，正常外链保持可点击。

## 页面与交互

`/blog` 出现在全站主导航和站内跳转搜索中。首页提供到博客的清晰入口。博客首页用本站暖白底、深灰文字、绿色主色和衬线标题，突出一篇主文章，其余文章按发布日期排列。分类筛选和即时搜索可组合使用，URL 保存筛选状态，刷新或分享链接后能还原结果。无匹配文章时给出清空筛选入口；零文章时说明博客正在整理并链接到“我的书”和 AI 实验室。

`/blog/:slug` 是阅读页：标题、摘要、发布日期和修订日期在开头明确标注，正文限制阅读宽度；桌面端目录保持可见，手机端目录可展开。读者可复制链接、使用系统分享（可用时）、回到列表、打开前后文章及同主题文章。交互按钮要有键盘焦点、反馈和移动端可用的触控尺寸。

文章末尾根据栏目展示已有产品的真实入口，例如《正念投资》、估值工具、AI Skills 或自由生活页，并清楚说明点击会去哪里。首版不显示无法完成的付费、订阅或咨询按钮；后续若有支付、订阅或联系服务，再在同一位置接入。投资文章继续使用本站现有风险提示口径。

## 与现有站点的接点

- 新增懒加载的博客列表和文章路由；主导航、跳转搜索及首页增加博客入口。
- 新增博客元数据的 SEO 描述、canonical、预渲染路由和 sitemap 条目。文章分享链接指向稳定的 `/blog/:slug`。
- 复用 `Page`、现有字体、颜色变量和响应式断点；博客 CSS 只管博客自己的布局，不改变投资与候选池页面。
- 当前工作区已有候选池相关未提交改动。实施时仅修改博客所需文件和共享导航的局部代码，不覆盖这些改动，也不把它们混入博客提交。

## 校验与验收

1. 用没有 frontmatter 的中文 Markdown 和含表格、图片、相对链接的样例验证导入、渲染和资源路径；未登记的审稿文件不会出现在公开列表。
2. 验证搜索与分类组合、空状态、直达文章 URL、目录锚点、分享反馈和手机布局。
3. 跑项目要求的类型检查与生产构建，确认博客文章进入预渲染和站点地图，原有路由正常。

## 首版边界

首版交付完整的博客基础设施和正式阅读体验。由于指定源仓库当前没有独立博客文章，首批公开文章数量取决于维护者明确登记的内容；不会把书稿全部重复发布，也不会凭文件修改时间生成“新文章”。博客的商业化先以现有书、工具和方向页面的真实转化入口体现，实际支付与邮件收集需要另行明确服务和数据处理规则。
