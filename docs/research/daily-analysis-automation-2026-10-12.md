# 每日分析：数据自动获取可行性核验

核验日期：2026-10-12。范围：原 `/daily-analysis` 的每日复盘表格，以及它使用的行情、涨停与存储接口。本文保留改造前的检查记录；后续已实现自动版与旧版迁移，当前运行方式见 [每日分析说明](../daily-analysis.md)。

结论：绝大多数字段具备自动获取或自动计算的条件。需要新增复盘数据聚合、交易日快照与前端自动加载逻辑；跌停打开及封板率需要补齐数据和定义，两个“前五”需要明确展示含义。

## 现有逻辑

- `src/pages/DailyAnalysis.tsx` 复用 `Pulse` 的 `analysis` 视图。
- `src/pages/Pulse.tsx` 的 `REVIEW_FIELDS` 定义日期和 16 项复盘指标，均由表单填写。`handleAddToday` 只填入日期，`handleSaveReview` 将空数值转为 0 后保存。
- `src/utils/storage.ts` 的 `loadReviews` / `saveReviews` 读取与写入浏览器 `pulse_daily_reviews`，最多持久化 365 条。
- 页面下方的指数、板块行情会自动请求，但结果只写入 `categories` / `sectorCategories`，没有生成复盘记录。
- 页面“更新于”是行情请求结束后的客户端时间，不是复盘数据的实际交易日期或采集时间。
- `/api/pulse-sync` 同步已有复盘记录；它没有采集市场数据的功能。
- 板块列表按涨跌幅排序，没有资金流字段，不能用来直接填充“流入/流出”。
- `fetchAkShare` 虽有调用封装，但默认连接本机 8080；部署文档明确 AKTools 服务未部署，不能视为线上现成数据源。

## 字段映射与口径

| 字段 | 自动化方式 | 必要约束 |
| --- | --- | --- |
| 日期、星期 | 按北京时间及交易日历生成 | 区分实际数据日期与用户查询日期；休市不生成虚构记录 |
| 涨停板数、跌停板数 | 涨跌停股池，按股票代码去重计数 | 固定沪深/北交所、ST、新股等统计范围 |
| 涨停打开数、涨停封板率 | 涨停池与炸板池 | 明确“打开”指收盘未封住的股票数，还是盘中曾开板的股票数/次数；这些指标不可混用 |
| 跌停打开数、跌停封板率 | 补齐曾触及跌停、收盘已打开的股票集合 | 跌停池的开板次数只描述池内股票，无法代表所有触及跌停后获救的股票；不能直接套用涨停的计算 |
| 量能（亿） | 汇总所选股票范围的成交额，换算为亿元 | 定义为成交金额；不能用成交股数替代，也不能叠加已经包含在深市内的创业板成交额 |
| 涨-跌 | 全市场快照按相对昨收的涨跌分类计数 | 明确平盘、停牌及统计市场；不能相加概念板块家数，成分股会重叠 |
| 沪深创 | 上证、深证成指、创业板指涨跌幅 | 固定三个指数，统一显示涨跌幅或正负号 |
| 连板数量、最高板 | 真实连续涨停梯队或涨停池连板数 | “3天2板”不等于“2连板”；不能直接使用现有 `up_num` 正则提取结果 |
| 连板晋级率 | 比较相邻交易日的股票集合及连续涨停高度 | 明确分母是昨日全部涨停股票还是昨日连板股票；昨天必须是上一交易日，缺失分母不显示 0% |
| 成交金额前五、换手率前五 | 全市场按成交额、换手率排序，取前五 | 现有数据类型只能存一个数字；若显示股票名单及各自数值，需扩展类型、展示及同步协议。汇总数字则需定义合计/均值 |
| 流入板块、流出板块 | 板块主力资金净流入排名 | 固定行业或概念分类及排名数量；保留数据源口径，不能以涨跌幅排名代替 |

## 接口实测

2026-10-12 进行了以下只读请求。以下是一次探测结果，不代表接口的长期稳定性或全市场覆盖保证。

1. 生产站点 `/api/cls-plate?date=20261009&up_limit=1` 返回 `code: 200`：13 个板块、72 行且 72 个唯一股票代码；股票时间日期为 2026-10-09。响应还包含当前解析器未使用的 `continuous_limit_up` 连板梯队，可作为连续涨停统计的候选来源。按概念收录的涨停列表是否覆盖所选全市场范围仍需交叉核验。
2. 东方财富 `getTopicZTPool` / `getTopicZBPool` / `getTopicDTPool` 返回有效股池，分别含 `lbc` 连板数、`zbc` 炸板次数、`oc` 开板次数等字段。
3. **上述三个东方财富请求都传入 `date=20261009`，实际响应 `data.qdate` 都为 `20261012`。** 因此仅传查询日期不能证明返回的是指定日期；禁止把这些响应存为 10 月 9 日的历史记录。
4. 东方财富 `push2` 的指数列表、成交排名、资金流排名三个请求在本次环境返回空响应，尚未验证可用。需调整接入方式或换源，并验证线上运行环境；文档中的接口存在不等于当前部署可以成功采集。

## 建议实现

1. 增加服务端复盘聚合接口。逐来源校验交易日期、股票范围、分页完整性及数值单位，响应包含实际交易日、获取时间、来源、字段缺失信息和统计口径。
2. 进入页面自动读取最近交易日的复盘快照，提供刷新及日期查询。盘中标为临时值；失败保留上次成功数据，未取得的字段显示 `—`。
3. 在北京时间收盘后运行定时采集并持久化每日快照；即使用户当天没有打开页面也应归档。当前工作流没有每日复盘采集任务，需要新增。具体时刻应在核实数据源日终更新时间后确定。
4. 自动采集结果与人工修正分别保存。现有按日期保存和整份云同步不能直接充当字段级的修正合并逻辑；新增自动快照不应覆盖人工记录。
5. 历史数据优先读取已归档快照；补采时只接受日期匹配的响应。免费股池文档仅承诺近期数据，较长历史需另接支持历史查询的数据源。

## 待明确

- 两个“前五”：股票名单及各自数值，还是成交额合计、换手率均值。
- “打开”采用股票数还是次数；晋级率采用昨日全部涨停还是昨日连板股票作分母。

其余实现选择可默认采用沪深 A 股、统一数据源口径、收盘快照及缺失值明确展示，并在页面说明范围。
