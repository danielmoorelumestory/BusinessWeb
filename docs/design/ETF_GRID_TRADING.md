# ETF 网格交易功能迁入设计

## 状态

已通过用户审阅。实现范围以本设计和后续已确认的实施计划为准。

## 目标

将 `/Users/hassan/Downloads/notes` 中的 ETF 网格操作功能完整迁入 BusinessWeb，尽可能保留计算、回测、记录管理和复盘能力。功能是行情分析与模拟，不提交真实委托。

## 必须遵守的云端数据边界

- 不连接、不读取、不写入 notes 项目朋友现有的 Cloudflare Worker、D1 数据库或同步 token。
- 不在新项目中保留朋友的 Worker URL、数据库 ID、密钥或默认同步目标。
- 初始状态为本地模式，所有网格记录和设置只写入 BusinessWeb 自己的浏览器存储。
- 完整 JSON 导入/导出作为跨站迁移和备份通道。导入先校验版本和结构，提供预览与合并/替换选项；默认合并，遇到同 ID 冲突时保留本地项并让用户选择，绝不静默覆盖。
- 云同步 UI 明确标注“未配置”。只有用户配置独立的同步服务 URL 与专用 token 后，才显示/启用同步。服务必须是为 BusinessWeb 单独部署的实例和数据库；不能接受或预填朋友项目的地址/token。服务端 owner/key 空间独立。没有独立服务时其余功能完整可用。
- 配置服务地址时进行明确确认，展示将访问的域名；拒绝朋友已知 Worker 地址及 notes 的硬编码地址。所有同步写操作只能针对用户刚配置并确认的独立服务。

## 入口与页面

在 React Router 和全局导航中增加“网格交易”入口，拆成三个路由：

1. **计算器**：选择 ETF/股票代码、输入网格步长/反弹/回撤等参数、选择回测区间、运行模拟、查看汇总和权益图，并保存为记录。
2. **记录列表**：浏览、排序、搜索和删除记录；刷新最新行情；调整策略参数；查看记录的同步状态；提供 JSON 导入/导出入口。
3. **记录详情**：展示策略指标、权益/资金/价格图、交易明细和参数阶段；支持调整模拟成交、手动补录/删除交易、恢复自动成交、创建和比较回测快照。

遵循 BusinessWeb 现有 React、React Router、lucide-react 和视觉样式，不引入新的图表依赖；交互图使用 SVG/Canvas，优先复用项目现有图表基础。

## 需要保留的领域规则

- 支持 A 股六位代码和 ETF；证券市场识别规则与 notes 对齐，并在界面显示识别结果。
- 继续使用无需登录的公开行情源：腾讯前复权日 K 线及实时行情。网络/CORS/解析失败时清晰报告，不伪造成功结果；本地缓存行情并标识数据时间。
- 沿用 notes 的费率规则：ETF 佣金 0.015%、单笔最低 ¥5；普通 A 股佣金按 0.015% 且不加最低佣金；A 股卖出印花税 0.05%，ETF 免印花税。费率集中为可版本化配置，并在结果中展示。
- 按 notes 模拟规则计算：买入触发价为上次成交价减步长加反弹，卖出触发价为上次成交价加步长减回撤；以日线最低/最高价判断触发，开仓当天不触发网格；同日买卖都触及时买入优先，每日最多一笔。显著标注日线回测的成交顺序假设和它不是实盘成交的限制。
- 使用前复权日线回测，计算已实现/总盈亏、持仓、现金流/资产、占用/最大资金、交易计数、触发价及权益序列。保留 notes 的资金模型：每次网格买入不受预设现金上限约束，卖出不得超过现有持仓；不可悄悄加入会改变回测结果的预算上限。在此默认之上提供两个可选护栏（不填则行为与 notes 完全一致）：价格下沿——网格买入触发价低于该价时永久停止买入（卖出不受影响，持仓可继续出清），并在结果中记录首次触及日期；资金预算——不改变回测行为，仅在最大资金占用超过预算时给出显著告警。
- 网格成交价、金额、股数可调整；金额与股数互斥。参数变化写入历史阶段，只影响变更之后的模拟，不追溯重算旧成交。
- 手动交易计入账户汇总但不改写模拟成交；可删除/恢复自动网格成交，开仓记录不可删除。
- 快照冻结其输入和结果，最多 20 个。快照续算从快照锚点做纯网格推演，比较原快照、纯网格续算和包含实际调整的当前账户，并限定快照中的更改不会污染主记录。
- 快照视图只读参数历史、手动交易和自动成交删除状态；可以独立调整快照中的成交价、金额和股数，且这些改动不得写入主记录。
- 保留详情页原有图表用途：价格、持仓市值、资金阶梯、总盈亏、后续网格价位，以及 hover 十字线和提示。小屏布局可调整，但不能丢掉数据系列。
- 列表排序至少覆盖更新时间、最后买入/成交、占用资金和盈亏；批量删除需要确认。

## 数据模型与存储

新增独立 `grid-trading` 领域模块，拆分行情适配、模拟引擎、费用、记录仓储、导入导出、可选云同步和图表序列生成；页面不得自行复制交易算法。

持久化沿用 notes 的记录结构和字段语义（`SavedRecord.row/result`、`GridParams`、`Trade`、`Overrides`、`ParamStage`、`ManualTrade`、`Adjustments`、`Backup`），但定义 BusinessWeb 自己的版本化 key，例如 `businessweb.grid-trading.v1`。导入器必须支持从 notes 导出的 `SavedRecord[]`，不要求用户手工转换；支持当前版本的 schema 校验与升级。记录保留 `id`、`savedAt`、`updatedAt` 等兼容字段，添加独立 schema 版本。本地存储容量不足时保留已有数据并给出导出/清理提示。

JSON 导出包含完整记录、备份、参数历史、成交调整、手动交易和 schema 版本；默认不导出同步 token。导入支持文件选择和拖放、校验报告、预览数量、逐记录合并/跳过/替换。不得提供会无提示清空当前全部记录的导入行为。

## 行情与模拟边界

- 行情请求集中封装，限制分段长度和并发，处理 GBK 响应、超时、空数据和服务限流。
- 缓存 key 区分证券、复权类型和日期范围；报价缓存标注短时效，K 线缓存可复用。提供手动刷新。
- 每份回测记录保存所用行情源、数据时间、回测区间、费率版本和算法版本，便于复现。
- 结果应能区分行情缺失、参数错误、卖出超过持仓等情况；避免静默地产生不完整回测。网格买入沿用 notes 的资金模型，不因现金余额不足而跳过；唯一例外是用户显式填写的价格下沿，触及后停止买入属于用户主动设置的纪律，不是静默的资金约束。

## 云同步实现约束

首期实现独立同步接口契约和本地配置/状态，但默认无服务地址。部署独立 Worker/D1 是启用云同步的前置条件；该服务单独建库、单独 token 和命名空间。同步协议沿用 GET 读取 records、PUT 写入 `{ records }` 的形状，但仅对显式配置的独立服务执行；按记录更新时间合并，较新的删除标记优先，删除 tombstone 保留 180 天。同步协议须支持版本化 payload、冲突检测和可读错误。同步前展示目标域名及待上传记录数，提供取消入口；同步后展示结果。

不得复用 notes 项目的 endpoint、数据库、token、owner key 或既有线上数据。除非部署了明确隔离的新服务，否则云同步按钮保持禁用；JSON 迁移仍可用。

## 验收标准

- 在 BusinessWeb 中可以从导航打开计算器、记录列表和详情，完整运行、保存、重载和删除一份回测。
- 一组固定 OHLC/参数的模拟结果与 notes 算法一致，包含费率、触发优先级、持仓、资金和盈亏。
- 参数分段、成交调整、手动交易、删除/恢复自动成交、快照续算/比较均能单独验证且互不污染。
- 权益图呈现原有关键数据系列，并能查看具体时点值。
- JSON 往返导入导出保留所有记录子结构；错误文件不会破坏现有数据。
- 默认配置下无任何网络同步请求，且源码及产物中不含朋友的同步 URL、D1 ID 或 token。
- 配置独立同步服务之前，用户数据始终保存在本地；配置之后，同步只访问确认过的独立目标。
- 手机和桌面可用；生产构建通过。
