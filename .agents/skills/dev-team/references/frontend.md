# Frontend 流程（先读 common.md）

## 阶段与产出
1. **发现**：框架/构建工具/语言、路由、状态管理、数据请求方案、样式体系与设计令牌、组件库、i18n、浏览器支持范围、lint/类型/测试/E2E 命令、dev server 启动方式。
2. **需求**：用户故事 + 验收标准；页面/组件清单；响应式断点；浏览器/设备范围；SEO/性能/i18n 要求；数据字段与错误场景。
3. **设计（UI）**：信息架构、布局与组件拆分、复用现有令牌与组件（缺口才新增）、**交互状态表**、a11y 要求、接口需求（字段/错误/分页）。无设计稿时先给线框级结构并标"待设计确认"，不当最终视觉。
4. **实现**：类型 → 数据层 → 组件 → 页面/路由 → 样式。
5. **联调**：与真实或 mock 接口对接。
6. **验收**：见下。

## 交互状态（数据驱动界面逐项说明）
加载（骨架）→ 成功 → 空 → 部分数据 → 错误（可重试）→ 无权限 → 离线/超时 → 提交中（防重复提交）→ 提交成功/失败反馈。
控件态：default/hover/focus/active/disabled/selected/invalid/read-only。表单：校验时机、错误文案位置、保留输入、破坏性操作确认。主题（深色等）项目支持则同步覆盖。

## 可访问性
语义化 HTML 优先于 ARIA；键盘全可用、焦点可见且顺序合理、对话框焦点管理；alt/label/aria-describedby；对比度（文本 ≥4.5:1，大字与 UI 组件 ≥3:1）；不只靠颜色；尊重 prefers-reduced-motion；200% 缩放不丢内容。有自动化工具（eslint a11y/axe）则跑，没有就人工核对并标"自动审计未执行"。

## 接口联调
先读契约；契约缺失先确认字段再写类型，不凭 UI 猜。无后端用项目既有 mock 方案，mock 与契约同构并标"基于 mock 验证"。统一处理 401/403、字段级校验错误、服务错误、超时/取消、重试与防重复提交、分页排序过滤、请求竞态、缓存失效。地址与密钥走项目既有环境变量机制。联调记录每个接口的成功/空/错误/慢/鉴权过期的实际观察。

## 验收
1. 静态：lint、类型检查、构建（命令取自发现阶段）。
2. 单元/组件测试：报告数量与失败。
3. 浏览器：启动 dev server 核对关键流程；有 Playwright/Cypress 配置则用。
4. 视觉：窄屏+宽屏、深浅色、加载/空/错误态。
5. 无法启动（依赖未装、缺变量、后端不可用）→ 标注，退而做类型检查与构建，并列手动步骤。性能结论仅在有 Lighthouse/体积报告时给出。

## 所有权与依赖
- 页面/路由（按 feature 目录）、共享组件与令牌/全局样式（单 owner）、数据层（API 客户端/类型/hooks/mock）、构建与依赖配置（单 owner）。
- 依赖：契约/类型 → 数据层 → 页面数据绑定（静态布局可基于类型草案并行）；共享组件/令牌 → 使用它们的页面；新依赖先于使用者。
