# 通用规则（所有端先读，本文件刻意保持精简）

## 授权
- 用户给的是功能范围。范围内可逆的开发修改（代码、本地配置、测试、文档）直接做，不逐次请求许可。
- 不可逆或对外动作超出现有授权时先确认：删除数据、生产迁移/部署/发布、推送远端、凭证、付费资源、范围外模块；已有明确授权继续有效。
- 歧义会改变产出时，集中问一次，不逐条打断。

## 栈与命令发现（开工第一步）
按序读取并记录来源，找不到写"未发现"，不猜：
1. README / CLAUDE.md / AGENTS.md / CONTRIBUTING / docs
2. 构建清单：package.json、settings.gradle*/libs.versions.toml、pom.xml、pyproject.toml、go.mod、Cargo.toml 等
3. 任务入口：Makefile / justfile / scripts / CI 配置（CI 中的命令是最可信的"真实可跑"证据）
4. lint/format/typecheck/test 配置、环境文件（.env.example、docker-compose、版本文件）

产出"项目事实表"：语言框架与版本、包管理器、构建/lint/类型检查/测试/启动命令、目录与模块边界、既有约定。沿用既有约定，不引入新框架或大版本升级，除非用户要求。

## 文件所有权
- 同一时刻一个文件只有一个 owner；并行任务派发前划定各自目录/文件，互不重叠。
- 共享文件（契约、依赖清单与锁文件、CI、根配置、全局主题、Manifest、迁移）指定单一 owner，他人只提变更请求（文件+原因+期望改动）。
- 生成物、锁文件只由执行生成命令者改，不手改。

## 任务卡与依赖
每个任务写：目标、输入（依赖的产出）、产出、owner 文件、验收方式。只写真实依赖（B 必须用到 A 的产出），无依赖则并行；不受影响的端不建任务。

## 验收诚实
- 只报告实际执行并看到输出的验证：命令、环境、结果摘要。
- 没跑/跑不了（缺环境、缺凭证、命令不存在）写"未验证：原因 + 用户可复制的命令"，不得编造"测试通过/真机验证"。
- 失败如实上报并附关键输出；不删除或弱化测试来变绿。

## 完成报告格式
做了什么 / 改动文件 / 已执行验证（命令+结果）/ 未验证项与原因 / 风险与后续。
