# Backend 流程（先读 common.md；无 UI 阶段）

## 阶段与产出
1. **发现**：语言/框架、分层、ORM 与迁移工具、数据库、鉴权方案、队列/缓存、配置与密钥管理、日志/指标/追踪、测试与 CI 命令、部署形态。
2. **需求**：业务规则、验收标准、非功能需求（吞吐/延迟/一致性）、数据与合规约束、失败与并发场景。
3. **契约**：沿用项目格式（OpenAPI/protobuf/GraphQL SDL/类型定义）。明确必填/可空、枚举、时间与金额格式、统一错误结构、分页排序过滤、鉴权要求、幂等要求、限流、版本与兼容。
4. **数据设计**：模型、索引、迁移（含回滚）、回填计划。
5. **实现**：路由/控制器 → 服务 → 数据访问 → 校验 → 鉴权 → 后台任务。
6. **自测** 与 7. **发布准备**（发布/回滚方案、监控项、变更说明）。

## 契约
契约先于实现；新增字段向后兼容，破坏性变更走版本或并行字段+弃用期；变更须通知所有消费方，由契约 owner 统一发布。

## 数据库迁移
用项目既有工具与命名；采用扩展-迁移-收缩（先加兼容结构→双写/回填→切读→最后删旧结构，分多次发布）；大表评估锁与耗时（在线加索引、分批回填）；每个迁移写明回滚方式，不可逆迁移（删列/删表/数据转换）单独标注并执行前向用户确认；本地或临时库演练升级→回滚→再升级，无库则标"迁移未演练"；未经授权不对真实环境执行迁移。

## 鉴权与授权
认证与授权分开，沿用项目方案；每个端点显式声明鉴权，默认拒绝；对象级授权防越权（IDOR）与字段级过滤；参数化查询、输入校验、防 SSRF/批量赋值；敏感字段不进日志与响应；密钥来自环境/密钥管理；CORS/CSRF/限流按项目现状补齐并说明。

## 幂等
创建/扣款/发消息类写操作用幂等键或业务唯一键+唯一索引；同键同参返回原结果，同键异参返回冲突；记录有过期策略。消费者与后台任务按"至少一次投递"设计（去重、事务边界）。并发用乐观锁或数据库约束防丢失更新。

## 可观测性
结构化日志（关联 ID、耗时、结果，脱敏）；不记录密码、令牌、完整证件/卡号；指标（请求量、错误率、延迟分位、依赖调用、队列积压、关键业务计数）；跨服务传递 trace ID；健康/就绪探针；告警阈值只作建议，不擅自配置生产告警。

## 回滚
发布方案含特性开关/灰度、迁移与代码的兼容顺序（先部署兼容代码→迁移→切换）、回滚触发条件与步骤、不可逆数据边界；新迁移已执行时旧代码仍能运行。产出方案与脚本，不执行部署或生产回滚（除非用户明确授权）。

## 验收
1. 静态：lint、类型检查、编译。
2. 单元测试；集成测试（用项目既有容器/夹具）。
3. 契约验证：本地启动服务后实际调用，记录状态码与响应样例。
4. 迁移演练（升级/回滚）。
5. 授权与滥用负向用例：未登录、越权、过期令牌、非法输入、重复提交。
6. 无 DB/缺外部凭证 → 标"未验证"，写所需环境与命令。

## 所有权与依赖
- 契约（单 owner）、数据（迁移与模型，迁移序号冲突由其统一管理）、业务（按领域模块目录）、基础设施（配置/依赖/CI/鉴权中间件/日志基座，单 owner）。
- 依赖：契约 → 控制器与消费方；模型 → 迁移 → 数据访问 → 服务；鉴权中间件 → 受保护端点；回填 → 读路径切换。
