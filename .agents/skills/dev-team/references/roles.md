# 角色、执行器与上下文

| 岗位 | 责任 | 输入 | 可交付产物 | 代码权限 |
|---|---|---|---|---|
| manager | 唯一用户入口；需求、验收、派工、资源、集成 | 用户目标、项目约束、各阶段证据 | 项目上下文、任务卡、管理交接、最终变更说明 | 用户授权范围内，可自行整合或派 integrator |
| architect | 模块/API/数据边界与实现方案 | 现有架构、行为需求 | 具体契约、目录分工、兼容性与验收说明 | 默认只读；共享契约修改由 manager 单独指定 owner |
| designer | 页面结构、交互状态、视觉/可访问性 | 用户路径、现有 UI/组件 | 结构/状态表、响应式与键盘行为要求 | 默认只读；需要原型时指定专属路径 |
| android | Kotlin/Java、Compose/Views、数据层和测试 | Android 方案、API 契约 | 客户端变更、实际构建/测试证据 | 任务指定模块 |
| frontend | 页面、组件、数据状态与联调 | 交互规范、API 契约 | Web 变更、浏览器/测试证据 | 任务指定 feature/组件 |
| backend | 业务、接口、鉴权、迁移、集成测试 | 契约、数据规则 | 服务端变更、数据库/接口验证 | 任务指定服务/迁移范围 |
| reviewer | 独立检查真实 diff 与风险 | 用户验收、实现 diff、测试证据 | 问题、严重度、复现依据、位置 | 代码只读 |
| qa | 核对行为与执行适用验证 | 契约、实现、审查结论 | 命令/退出码、观察结果、未测项 | 代码只读；报告目录可写 |
| researcher | 查官方文档、调查现状与替代方案 | 具体问题与版本/平台 | 来源/日期、结论、适用限制 | 代码只读 |

角色是职责，harness 是执行工具，模型是其配置。`agy` CLI 在 Orca 的 agent ID 是 `antigravity`；`opencode-m3` 是本技能的路由名，Orca 的 agent ID 是 `opencode`，模型 ID 单独传递。Codex/Claude 不强绑模型版本，沿用用户设置。

每个 worker 只接一个自包含任务，输入项目约束、相关代码、依赖产物、验收和所有权。不要复制整段 manager 聊天历史。按需给文件路径；持久进度在项目中，不依赖某家私有会话历史。worker 不自行扮演 manager 或启动下属。

默认最多 3 个并行执行者；`maxParallel: 1` 即低额度串行模式。减少研究/设计角色的独立会话可以省上下文，但必要的行为检查与审查仍须保留。跨 harness 审查是优先项；同一家实现和审查时用新的上下文，并在交付里说明。

manager 负责 API schema、共享类型、依赖清单/锁文件、路由总表、全局样式/主题、Gradle/Manifest、数据库迁移序号等共享文件的唯一归属。目录不重叠还不足以保证并行安全：同端构建输出、代码生成、测试数据库、服务端口也要分配，互相干扰则串行或 worktree 隔离。

报告至少含：任务与 Dispatch、产出与变更文件、执行命令/退出码、已知问题、未测项、下一步。引用实际文件和日志；权限边界是协作约束，不是 OS sandbox，继续遵守 harness 自身的权限机制。
