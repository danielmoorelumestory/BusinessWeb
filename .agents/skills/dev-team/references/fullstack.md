# Fullstack 流程（编排层；先读 common.md，再按涉及的端读 backend.md / frontend.md / android.md）

本文件只写跨端编排，不重复各端细节。只读实际涉及的端文件；不受影响的端不建任务。

## 顺序
1. **发现**：覆盖后端与所有涉及的客户端，产出一份合并的项目事实表。
2. **需求**：端到端用户路径 + 每端各自的验收项。
3. **契约（并行的前提）**：由唯一契约 owner 产出 API 契约（错误模型、鉴权、分页、幂等）、共享模型/枚举、示例请求/响应（兼作 mock 数据）、版本与兼容策略、事件/推送契约。评审后冻结；后续变更走"变更请求→契约 owner 修改→通知所有消费方"。
4. **并行实现**（契约冻结后）：后端按 backend.md；Web 按 frontend.md（基于契约类型+mock）；Android 按 android.md（基于契约模型+fake repository）。mock 服务器/夹具归契约 owner 或独立 owner。
5. **联调**：后端可用后各客户端从 mock 切真实接口，逐接口核对成功/空/错误/鉴权过期/慢响应。偏差按证据（实际请求与响应）归类：契约缺陷改契约、后端缺陷后端修、客户端误用客户端修；客户端不得私自适配契约偏差。
6. **端到端验收**：关键路径跨端走通；检查旧版本客户端（尤其移动端长期存活）与新后端的兼容。
7. **发布方案**：通常后端兼容变更→迁移→客户端发布→清理旧路径；含特性开关与回滚。只给方案，未经授权不执行发布。

## 依赖
```
发现 → 需求 → 契约(冻结) ─┬→ 后端 ──────┐
                          ├→ Web 前端 ──┼→ 联调 → 端到端验收 → 发布方案
                          └→ Android ───┘
```
只有联调依赖后端可运行；UI、状态模型、数据层适配都只依赖契约。

## 所有权
契约与共享类型单 owner，各端禁止私改；每端独占自己的目录；monorepo 根配置、依赖清单、CI 单 owner；由契约生成的代码由执行生成命令者提交且仅在契约变更时重生成；合并顺序契约→后端→客户端，冲突由 manager 仲裁。

## 验收汇总
