## 数学口径（PanoMath）

- `sliceSeries(series, range, anchor)`：区间是 `[anchor 往前 N 个日历年, anchor]`，两端都含。遇到不存在的日期按月末钳制，例如 2024-02-29 往前 1 年是 2023-02-28，2025-02-28 往前 1 年是 2024-02-28。anchor 默认取数据末日，anchor 之后的数据剔除。返回新对象，12 个字段与 `d` 对齐，缺失数组补 null，不改原对象。另附 `rangeStart/rangeEnd`。
- `stats`：只用有限数值（price 还要求 > 0），字符串、NaN、null 都不算样本。`percentile = #(≤最新) / count × 100`。q20/q80 用线性插值，与 numpy 默认一致。高低点日期取首次出现的那天。`changePct = (末−首)/|首|×100`，样本少于 2 个时为 null。`changeKind` 只有 price 才是 `'price'`，界面文案分开写成“区间涨跌（收盘点位）”和“指标区间变化（非指数涨跌）”。
- `drawdown`：以高水位计算。缺值或非正价格的位置保持 null，不补 0，也不更新峰值。没有有效价格时返回 null。另返回最大回撤日期及其之前的峰值日、当前回撤、峰值。
- `compare`：anchor 默认取各序列末日中最晚的一天，作为统一窗口。在窗口内取所有序列都有正收盘价的日期交集，以共同首日为 100。相关性的算法是：在共同日期轴上，每个 ISO 周（周一到周日）取最后一个观测；只有周序号恰好相差 1 的两周之间才算收益，缺周直接跳过，不补 0；然后算 Pearson。样本少于 3 个或方差为 0 时为 null，负相关原样保留。`counts` 是配对样本数矩阵，另附 `weeks`、`returnDates`、`method`。
- 另外导出几个辅助函数：`pearson / weeklyReturns / isoWeekIndex / minusYears / rangeStart / parseDate / lastDate / quantileSorted`。

## 详情 UI（PanoDetail）

`render(container, series, {range, metric, anchor, onChange})` 渲染以下区块：

- 标题区：代码、分类、成分股数和日期、收盘点位截至日、series.warnings。
- 指标切换（price/pe/pb/dy/mcap/amt）：没有数据的指标也能切过去，按钮上带“无数据”标记。
- 区间切换：1/3/5/10 年和全部。
- 主图：时间轴只画有效观测，带 20–80% 金色分位带和 20/80/均值参考线。
- 统计项：最新值和日期（字段日期早于收盘点位时会提示）、历史分位、20/80 分位、最高/最低及日期、均值、区间变化、有效样本数和频率（日、周、月频或稀疏）。
- 估值温度计：PE/PB/DY 三行，各用自己的日期和样本数。股息率取 100−分位。
- 回撤（二审后修订）：
  - 曲线和“近N年当前回撤/最大回撤”都用 `PanoMath.drawdown(PanoMath.sliceSeries(series, range, anchor))`，峰值只取所选区间内的收盘，区间前的高点不计入。
  - “全部历史最大回撤”另外用 `sliceSeries(series, 'all', anchor)` 计算，并附全部口径下的当前回撤。
  - 每项都标出峰值、峰日和谷日，脚注写明两种口径的起点。
  - 纯函数 `PanoDetail.drawdownSummary(series, range, anchor)` 供测试使用（只新增，不影响 render/dispose）。
- 小卡：股息率、ROE、成交额、样本股数，各带日期和来源。
- 盈利对照：收盘点位对照来源披露的 EPS 或 ROE；都没有时显示空态，明确不从点位或 PE 反推。
- 成交热度：成交额柱图，有换手率时叠加，另给成交额分位和近 20 个观测的均值。
- 来源与覆盖表：12 个字段逐一列出单位、来源和口径、观测数、首个日期、最新日期、最新值、频率。表格可横向滚动。

字段缺失时：区间内无观测会提示该字段最后一次观测的日期；字段完全没有时提示“数据源未提供，本页不推算、不填补”。

生命周期：
- 每次 render 先 dispose。
- 点击用委托监听，挂在本模块自己的根节点上。
- 全局只挂一个 resize 监听，带 120ms 去抖。
- dispose 会销毁图表、移除监听和根节点。
- 切换后焦点回到刚按的按钮。
- `onChange` 只负责通知，重绘由详情页自己完成。
- 名称和来源都经过 HTML 转义；链接只允许 http/https。

## 二审修订（回撤口径与连线说明）

- 问题：原 `drawdownData` 先对全历史算回撤再切片，标签却写“近N年最大回撤”，会把区间前的高点算进区间最大回撤。
- 修复：改用 `drawdownSummary`，区间口径和全部口径分开计算，见上文“详情 UI”。
- 新增回归测试 `tests/analytics.test.cjs`，在 vm 中加载 analytics.js 和 detail.js，所有数字都可以手算核对：
  - 数据：2025-06-02 的 price=100 在区间之前；近 1 年（锚点 2026-11-11）内 price=[80,90,85]。
  - 区间口径：最大回撤 = (85/90−1)×100 ≈ −5.5556%，不是 −20%；峰在 2026-03-02，谷在 2026-11-11；区间首点回撤为 0；当前回撤也是 −5.5556%。
  - 全部口径：最大回撤 −20%（峰 2025-06-02 → 谷 2026-01-05），当前回撤 −15%。
  - 另一个用例覆盖：区间内没有收盘时 range 为 null，全部口径仍可用；完全无数据时两者都是 null。
- 变异检验：把区间口径改回用全历史计算（`drawdown(fl)`），这 2 个新测试都失败。
- jsdom 实际渲染这组数据，回撤卡片输出：
  - “近1年当前回撤 −5.56%，相对区间高点 90.00（2026-03-02）”
  - “近1年最大回撤 −5.56%，峰 2026-03-02 → 谷 2026-11-11”
  - “全部历史最大回撤 −20.00%，峰 2025-06-02 → 谷 2026-01-05；全部口径当前回撤 −15.00%（相对 100.00，2025-06-02）”
- 修订后重跑通过：原冒烟脚本（监听和图表不泄漏、空态、焦点、XSS），以及真实 ECharts 5.6 SSR 的 4 个图。
- 连线问题：图表只连接有效观测点，本页无法区分休市和数据缺失，所以没有人为断线。主图脚注、回撤脚注和来源覆盖说明里都写明：连线不表示中间缺失日期有数据，应以覆盖表的观测数、日期和频率为准。

## 未验证项与风险

- 没有用真实浏览器做视觉、窄屏和交互验收，由 manager 统一完成，本 worker 没有占用 Orca 浏览器页。
- 写报告时 `data-bundle.js` 还不存在，没有用真实数据跑过。下面两点要在真实数据下确认：港股日期和 A 股日期交集后的样本量；PE 稀疏时的频率提示。
- 区间起点含起始当天。例如锚点 2026-11-11 的“近1年”从 2025-11-11 开始，比“严格 365 天之后”多一天。这是有意的口径选择，测试已固定。
- “全部历史”回撤的峰值只基于本数据集起点（区间口径只取区间内），都不是指数发布以来的峰值，页面已注明。
- 颜色按 A 股习惯（红涨绿跌），回撤用绿色。暗色主题未适配，如果首页启用暗色，需要协调 `--pd-*` 变量。
- 页面上没有 CSV 导出按钮。契约写明由首页 app 全局实现。
